# ADR-0013: Signed JSON plugin index, fetched by a client CriKey ships

Status: Accepted
Spec: §2.2, §21.2, §23.1, §23.3

## Context

Spec §2.2 lists a public plugin repository as later scope. CriKey does not host
one and this repository is the wrong place to build one, but without the *client*
half there is no way to discover a plugin at all: `crikey plugin install` accepts
a path or a URL an operator already knows, which is not discovery.

Two halves are separable. The hosting, the submission review and the moderation
are a service. The document format, the verification rules, the cache and the
commands are a client, and they are what decides whether a hostile or merely
broken index can make a launcher install the wrong bytes.

## Decision

**Format: one signed JSON document.** `index-version`, `generated-at`, and a
`plugins` array whose entries carry `id`, `name`, `version`, `runtime`,
`summary`, `homepage`, `licence`, `download-url`, `package-digest` and
`signer-fingerprint`. JSON rather than the TOML every other CriKey document uses,
because this is the only one that is generated by a machine, served over a
network and never hand-edited; TOML's array-of-tables is an affordance for a
human editor nobody here is. Member names stay kebab-case so one spelling
convention covers every CriKey document. Unknown members — top level and
per entry — are captured into an `extra` map rather than refused, so an index
generated for a newer client stays usable by an older one. A `runtime` this build
does not know is likewise kept as text: such an entry is searchable and simply
not installable here.

**Verification: through ADR-0012, never beside it.** The document is fetched
with its detached signature from `<url>.sig` and refused unless a key in the
user's trust store signs it — `verify_signed_manifest`, no crypto of our own.
The document is parsed only after the signature holds, so a hostile document
never reaches the parser on the strength of having been served. A verification
failure never falls back to the cache and never overwrites it: only a *transport*
failure may fall back, and that copy is reported `stale` with its age and the
reason. An installed package is refused unless it hashes to the entry's
`package-digest`, and the refusal names both digests.

**Transport: HTTPS through the existing `ureq` fetcher, plus `file://`.** No
second HTTP stack. `file://` is accepted on identical terms because the signature,
not TLS, is the trust boundary — which is what makes an air-gapped mirror, and
this crate's own tests, possible without a hidden test hook.

**Configuration: `launcher.plugin-index-urls`, default absent.** With nothing
configured there is no index, no network traffic, and the commands say so.

## Consequences

- `crikey plugin search`, `show`, `index update`, and `install <id>` exist; the
  indexed install reuses the one install pipeline, so its atomicity and rollback
  are the same code every other install runs.
- A launcher with no configured index behaves exactly as it did before.
- Bounded: 8 MiB per document, 20 000 entries, 4 KiB per field, 256 MiB per
  package — the same ceiling a URL install already has.
- `serde_json` becomes a dependency of `crikey-package-manager`. It is already
  in the workspace for the Python transports.
- The publishing side — generating and signing a document — is a tool this
  repository does not ship. Anything that can emit this JSON and sign it with
  ADR-0012 keys is a valid publisher.

## Alternatives rejected

- **TOML, for consistency.** Consistency with hand-edited files, at the cost of
  a format whose parse tree cannot hold an unknown value without a
  `toml::Value`, for a document no human edits.
- **Per-entry detached signatures instead of a signed index.** One signature per
  plugin, fetched per search hit: N round trips to rank a query, and no way to
  detect an entry an index silently dropped.
- **A hardcoded default index URL.** A network request nobody asked for, to a
  host this project does not run.
- **Trusting TLS instead of a signature.** Then the CDN, and anyone who can
  mis-issue for it, decides what installs.
